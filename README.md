# Vibha & Kaustubh : Wedding Celebrations

A React + TypeScript + Vite photo gallery for the Haldi and Wedding celebrations (February 2023), with ceremony proceedings from the wedding program.

## Features

- **Landing page** : peacock wedding invitation theme with navigation tiles
- **Haldi** (`/haldi`) : photo gallery with sunflower/turmeric hero
- **Wedding** (`/wedding`) : photo gallery with blush/rose welcome hero
- **Ceremony proceedings** (`/wedding-proceedings`) : step-by-step timeline from the wedding program PDF
- **Light / dark theme** and **4 languages** (English, Hindi, Punjabi, Bengali)
- Lazy-loaded galleries, lightbox with swipe/download/progress, floating section decorations

## How images are bundled

The site uses **two different image strategies**. Understanding which is which matters for development and deploy.

### 1. Bundled hero assets (`src/assets/`)

Hero invitation images are **imported in components** and processed by Vite:

```tsx
import landingHero from "../assets/landing-hero.png";
```

- Vite copies them into `dist/assets/` with a **content hash** (e.g. `landing-hero-yI5CGs4v.png`)
- Optimized and cache-busted automatically on each build
- Used only for section headers (landing, Haldi, Wedding heroes)
- `landing-hero.png` is also **regenerated in HD** by the sync script from `~/Desktop/og-preview.jpg`

### 2. Static public files (`public/`)

Files in `public/` are copied **verbatim** to the dist root (no hashing, no import):

| File | Purpose |
|------|---------|
| `og-preview.jpg` | WhatsApp / Facebook link preview (1200×630, generated by sync script) |
| `album/{id}/manifest.json` | Ordered list of photo filenames per album |
| `album/{id}/full/*` | Full-size gallery images for the lightbox |
| `album/{id}/thumbs/*.webp` | Grid thumbnails (500px wide WebP) |

The gallery **never imports album photos**. At runtime it:

1. Fetches `album/{id}/manifest.json`
2. Renders grid cells with `album/{id}/thumbs/{name}.webp`
3. Loads full images on demand in the lightbox via `XMLHttpRequest` + blob URLs

This keeps the JS bundle small and avoids bundling hundreds of photos.

### 3. Album sync pipeline (`scripts/sync-album.mjs`)

Runs automatically before `dev`, `start`, and `build`:

```
~/Desktop/Haldi/   ──► public/album/haldi/full/   + thumbs/ + manifest.json
~/Desktop/Wedding/ ──► public/album/wedding/full/ + thumbs/ + manifest.json

~/Desktop/og-preview.jpg (or src/assets/landing-hero.png)
                   ──► public/og-preview.jpg      (1200×630 social preview)
                   ──► src/assets/landing-hero.png (2400px HD landing hero)
```

**Thumbnail generation**

- Source photos are copied to `full/` unchanged
- `sharp` generates 500px-wide WebP thumbs (quality 75, EXIF rotation applied)
- Results are cached in `.cache/album-thumbs/` so re-syncs are fast
- `manifest.json` lists filenames in natural sort order

**What is gitignored**

```
public/album/    # ~400 photos : too large for the repo
.cache/          # Generated thumb/OG cache
dist/            # Build output
```

Hero PNGs in `src/assets/` and `public/og-preview.jpg` **are committed** so the site builds without Desktop folders (galleries will just be empty until sync runs locally).

## Setup

```bash
npm install
npm run dev
```

Place photo folders on your Desktop (or edit source paths in `scripts/sync-album.mjs`):

- `~/Desktop/Haldi`
- `~/Desktop/Wedding`

## Scripts

| Command | Description |
|---------|-------------|
| `npm run dev` | Sync albums + start Vite dev server |
| `npm run build` | Sync albums + TypeScript check + Vite build + SPA fallback |
| `npm run preview` | Preview production build locally |
| `npm run deploy` | Build and publish `dist/` to GitHub Pages |

Production builds serve at the site root (`/`) on `https://wedding.kaustubhdutta.com` (see `public/CNAME` and `.env.production`).

## Tech stack

- **sharp** : album thumbnail and OG image generation at sync time
